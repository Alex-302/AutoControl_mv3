## Physical-test sessions (the engine DROPS synthetic input)

The engine ignores injected input (`LLMHF_INJECTED`), so a wheel / gesture test
must be driven by a real hand. Everything below exists to squeeze data out of
such a session — the tools themselves are in the generated inventory at the
bottom; these are the rules that make the data trustworthy:

- **Work with the MAXIMIZED window of the RIGHT process.** Chrome keeps SEVERAL
  top-level windows per process (one visible, others hidden), and a window with
  many tabs hides its close buttons — probing zone 15 there measures nothing.
  Never touch a minimized window. `_probe_winlist.ps1 -ProcId <pid>` lists the
  windows with their rects and the minimized flag.
- **Every cursor move must be DPI-aware.** Without `SetProcessDPIAware` a
  `SetCursorPos` call takes LOGICAL coordinates and lands at 1.5× the requested
  point on this 150% display — probes then measure a different spot and it looks
  like "a fresh helper misclassifies". Use `_probe_mouse.ps1`, not the shared
  `_ac_mouse.ps1` (which also hardcodes Chrome SxS and uses an ALT-hold
  foreground trick that OPENS the Opera menu and changes the zone answer).
- **Chrome evicts an idle service worker ~30 s after the last CDP client
  detaches** — that kills every runtime probe. Hold a session with
  `node Test/_probe_hold.js <port> <seconds> "<regex>"` in a second terminal
  while the user tests; it also prints the SW console live.
- **A browser you may NOT relaunch with a debug port can still be observed.**
  Chrome 136+ ignores `--remote-debugging-port` on a default profile anyway, so
  for the user's main browser: the action target is readable from the profile's
  LevelDB (`Local Extension Settings\<ext-id>\000003.log`, open it with
  `FileShare::ReadWrite`), and the SW can report to the helper, which appends to
  `%TEMP%\ac_zone_helper.log` (see `Docs/GOTCHAS.md`, the note-channel entry).
- **Ask the browser-spawned helper, not a standalone one.** A standalone
  `zone_probe.ps1` / `zone_helper_smoke.js` run has no browser in its parent
  chain, so its "own window" gate is inert and it answers `[1]` for points over
  ANY window. For a real answer go through the SW:
  `node Test/cdp_eval.js <port> "__acTest.zoneAsk(1000)" --await` returns `[0]`
  when the cursor is not over that browser.
